# Snapshot-Based Navigation of MAVs Using Satellite Imagery

Code and configuration for the bachelor thesis

> **Snapshot-Based Navigation of MAVs Using Satellite Imagery: A Simulation Study in Project AirSim**
> Issa Ghazi, Hochschule Bielefeld (HSBI), Faculty of Engineering and Mathematics, 2026
> Supervisor: Dr. phil. Fabian Steinbeck · Second examiner: Prof. Dr.-Ing. Wolfram Schenck

The thesis asks at which flight altitude snapshot-based visual navigation fails when the
two phases of teach-and-repeat come from different image domains:

- **Teach:** real orthographic aerial imagery (Geobasis NRW digital orthophotos, WMS).
- **Repeat:** perspective nadir images rendered in Project AirSim / Unreal Engine 5.7 from
  Google Photorealistic 3D Tiles (Cesium for Unreal).
- **Matching:** rotational image difference function (RIDF) after Gaffin et al. (2015),
  reference sensor 50 × 50 px with 10 gray levels.

Experiments: altitude sweep on three routes (open loop), sensor sweep (15 sensor
variants), within-domain controls on five routes, an RGB-versus-near-infrared comparison,
and closed-loop route recapitulation with Gaffin's arc-scan agent.

## 3. Setting up the simulator

Project AirSim is built from source and runs inside its **Blocks** Unreal project, to
which the Cesium for Unreal plugin is added. Apart from the two build fixes in
`patches/`, the only change to the Project AirSim checkout is enabling the Cesium
plugin; all experiment-specific settings live in `sim_config/` and in the Unreal level.

### 3.1 Build Project AirSim

The official build instructions are at
<https://iamaisim.github.io/ProjectAirSim/development/use_source.html>; the steps below
are the ones used for the thesis.

1. Install Visual Studio 2022 (C++ workload) and Unreal Engine 5.7.
2. Pin the MSVC toolset for Unreal in
   `%APPDATA%\Unreal Engine\UnrealBuildTool\BuildConfiguration.xml`:

   ```xml
   <?xml version="1.0" encoding="utf-8"?>
   <Configuration xmlns="https://www.unrealengine.com/BuildConfiguration">
       <WindowsPlatform>
           <CompilerVersion>14.44.35207</CompilerVersion>
       </WindowsPlatform>
   </Configuration>
   ```

3. Clone the fork at the commit used and apply the two build fixes (a missing forward
   declaration of `WorldSimApi` in `UnrealScene.h` and a missing include for
   `UUnrealCamera` in `UnrealScene.cpp`):

   ```powershell
   git clone https://github.com/iamaisim/ProjectAirSim.git D:\dev\ProjectAirSim
   cd D:\dev\ProjectAirSim
   git checkout f777efe9b030aba4a76fa3d2036246afcf0f1b43
   git apply <path-to-this-repo>\patches\projectairsim-f777efe-build-fixes.patch
   ```

4. In an *x64 Native Tools Command Prompt for VS 2022*, from the checkout root:

   ```bat
   build.cmd blocks_development
   cd unreal\Blocks
   blocks_genprojfiles_vs2019.bat
   ```

   Open the generated `Blocks.sln` in Visual Studio 2022, select **Development Editor /
   Win64** and start it (F5). Visual Studio builds the plugin and the Blocks project and
   opens the Unreal Editor. Afterwards the editor can be started directly:

   ```bat
   "C:\Program Files\Epic Games\UE_5.7\Engine\Binaries\Win64\UnrealEditor.exe" "D:\dev\ProjectAirSim\unreal\Blocks\Blocks.uproject"
   ```

5. In the editor: *Edit → Editor Preferences*, search "CPU", and uncheck
   **Use Less CPU when in Background**; otherwise the simulation throttles while the
   Python scripts run in another window.

### 3.2 Add Cesium for Unreal and the 3D tiles

1. Install **Cesium for Unreal 2.27.0** for UE 5.7 from Fab / the Epic Games Launcher
   (*Install to Engine*).
2. In the Blocks project: *Edit → Plugins*, enable **Cesium for Unreal**, restart the
   editor. (This adds the plugin entry to `Blocks.uproject`.)
3. Create a free Cesium ion account. *Window → Cesium → Connect to Cesium ion* and create
   or select a default access token. The token is stored in the local Unreal project and
   must never be committed anywhere.
4. Create a new empty level and save it (the thesis level is `Content/cesium.umap`).
5. From the Cesium panel (*Quick Add*), add **CesiumSunSky** and
   **Google Photorealistic 3D Tiles** (Cesium ion asset 2275207). Adding the tileset
   also creates the **CesiumGeoreference** actor.
6. Set the level parameters used in all experiments:

   | Actor | Setting | Value |
   |---|---|---|
   | CesiumGeoreference | Origin Latitude / Longitude | 52.040111 / 8.495097 |
   | | Origin Height (ellipsoidal) | 800.0 m |
   | | Rotation | none (unrotated, see `--ned-x-bearing 90`) |
   | Google Photorealistic 3D Tiles | Maximum Screen Space Error | 16 |
   | CesiumSunSky | Date | 21 September 2019 |
   | | Time Zone | **+2.0** (the initial value −5.0 puts the sun almost on the horizon) |
   | | Solar Time | 12.28 (≈ 12:17, solar elevation ≈ 36.2°) |

7. Press **Play**. The simulator now waits for a Python client.

The georeference origin must match `home-geo-point` in
`sim_config/scene_snapshot_repeat.jsonc` and the `--origin-lat/--origin-lon/--origin-h`
arguments of the scripts (defaults are already set to these values).

### 3.3 Simulator configuration

`sim_config/` is read by the Python client and sent to the simulator when the scene is
loaded (`World(..., sim_config_path=...)`); nothing has to be copied into the Unreal
project.

- `scene_snapshot_repeat.jsonc`: scene with one robot `Drone1`, steppable clock, geo
  origin identical to the CesiumGeoreference.
- `robot_quadrotor_nadir_nonphysics.jsonc`: **non-physics** vehicle (placed with
  `set_pose`, no flight controller) with two cameras:
  - `DownCamera` (nadir): RGB 906 × 906 px at 109.47° FOV, motion blur off, fixed
    exposure, plus a 256 × 256 px planar-depth image (90°) for ground-level estimation.
    The central 640 × 640 px crop of the RGB frame is exactly a 90° camera; the larger
    capture lets the RIDF rotate the image without black corners entering the
    footprint.
  - `Chase` (viewport, streaming only): also points nadir, because Cesium streams tiles
    for the viewport camera; otherwise black tile gaps appear in the `DownCamera` frames.

## 5. How the algorithm is connected to the simulator

Project AirSim is used as a **positionable camera, not as a flight simulator**. The
experiment scripts access it only through the class `SimLink` in
`scripts/capture_repeat.py`, which `recapitulate_route.py` reuses unchanged. In
simplified form:

```python
from projectairsim import ProjectAirSimClient, World, Drone

client = ProjectAirSimClient()
client.connect()
world = World(client, "scene_snapshot_repeat.jsonc", delay_after_load_sec=2,
              sim_config_path="sim_config")
drone = Drone(client, world, "Drone1")

drone.set_pose(pose, reset_kinematics=True)       # non-physics teleport (NED)
imgs = drone.get_images("DownCamera", [0, 1])     # 0 = RGB 906 px, 1 = planar depth
```

One observation passes through the following chain:

```text
route waypoint (lat, lon)
 -> exact WGS84 ECEF -> ENU at the Cesium georeference -> AirSim NED (--ned-x-bearing 90)
 -> set_pose, yaw = route bearing
 -> settle loop: grab frames until two consecutive ones agree and depth is complete
 -> ground level from planar depth (95th percentile), correct to the requested AGL
 -> RGB frame (BGR -> RGB)
 -> snapshot_lib.rotate_and_crop + preprocess_view, for every rotation 0..359 deg
 -> RIDF against all teach scenes of that altitude -> best scene, heading
```

- **Open loop** (`capture_repeat.py`, then `evaluate_ridf.py`): the simulator only
  produces frames at known poses; matching runs afterwards, without the simulator.
- **Closed loop** (`recapitulate_route.py --world sim`): the RIDF decides where the next
  frame is taken. Seven candidate poses on an arc of radius 10 m ahead of the agent are
  captured and matched against the whole library; the agent moves to the most familiar
  one (lowest `d_best / mean(D)`), and the visual compass sets the next scan direction.
  With `--world wms` the same agent runs on fresh orthophoto crops instead of the
  simulator (no domain gap).

Teach and repeat use the **same** preprocessing code (`snapshot_lib.py`): grayscale
(ITU-R 601) → per-scene histogram equalization → area downsampling to N × N →
quantization to the gray levels → circular mask. Any change to this module invalidates
existing teach libraries.

## 8. Teach phase

`extract_route_snapshots.py` requests one north-up orthophoto square per waypoint from
the Geobasis NRW WMS (layer `nw_dop_rgb`, EPSG:25832) at a **constant source GSD of
0.20 m/px** for every altitude, rotates it to the route bearing and derives all sensor
variants offline. The footprint is `2 · h` (90° field of view); only the footprint
changes with altitude, never the source detail.

```powershell
# dry run: geometry and request count, no network
python scripts\extract_route_snapshots.py --route routes\route_s.csv `
    --altitudes 30 40 45 50 60 80 100 140 200 300 `
    --resolutions 10 20 40 50 80 --gray-levels 2 10 100 `
    --spacing 5 --fov 90 --src-gsd 0.20 --out data\teach_innenstadt --dry-run

# real run: same command without --dry-run
```

Use one library folder per route (`data\teach_sudbrack`, `data\teach_nordpark`,
`data\teach_wald`, `data\teach_acker`). Downloads are cached in `<out>\_cache_dop`
and validated; interrupted runs continue where they stopped. Truncated downloads can be
found and removed with

```powershell
python scripts\verify_cache.py --cache data\teach_innenstadt\_cache_dop --delete
```

and are fetched again on the next run.

## 9. Repeat phase (simulator)

`capture_repeat.py` places the non-physics drone at every waypoint and altitude, yawed
to the route bearing, measures the ground in the depth image, corrects the height to the
requested AGL and stores the settled RGB frame plus a `manifest.csv` per altitude.

```powershell
python scripts\capture_repeat.py --route routes\route_s.csv `
    --altitudes 45 50 60 80 100 140 200 300 `
    --origin-lat 52.040111 --origin-lon 8.495097 --origin-h 800 `
    --ground-z0 640 --teach-root data\teach_innenstadt --sim-config sim_config `
    --settle-thresh 0.6 --resume --out data\repeat_innenstadt
```

Per route, change `--route`, `--ground-z0`, `--teach-root`, `--out` and the altitudes
(table in Section 7). Settle thresholds used: **0.6 for Innenstadt, 1.0 for Sudbrack and
Nordpark** (Section 16). `--ground-z0` is only the initial guess for the first waypoint;
afterwards the ground is measured. `--teach-root` makes the script abort if its
waypoints differ from the teach manifest. `--dry-run` computes all poses without a
simulator.

Run only one simulator script at a time (one drone); WMS downloads and RIDF evaluations
may run in parallel.

## 10. RIDF evaluation and aggregation

`evaluate_ridf.py` rotates every repeat frame in 1° steps, preprocesses each rotation and
compares it with **all** teach scenes of the same altitude (sum of absolute differences
inside the circular mask). The global minimum gives the matched waypoint and heading.

```powershell
python scripts\evaluate_ridf.py --teach-root data\teach_innenstadt --alt 100 `
    --repeat-manifest data\repeat_innenstadt\alt_0100m\manifest.csv `
    --sensor 50 --gray 10 --step 1 --workers 8 --out results\innenstadt\alt_0100m
```

Repeat for every altitude into `results\innenstadt\alt_XXXXm\`, then

```powershell
python scripts\aggregate_results.py --results results\innenstadt `
    --control results\control_innenstadt --out results\figs_innenstadt
```

writes `summary.csv` (one row per altitude; committed as
`results_summary/open_loop/summary_<route>.csv`) and diagnostic figures. Main fields:
`loc_hit_5m_pct` (error ≤ 5 m), `fail_20m_pct` (gross failure > 20 m),
`loc_hit_gsd_pct` (error ≤ one sensor pixel), `yaw_median_deg`, `depth_median`
(RIDF depth at the true scene) and `alias_median` (true scene versus best competitor).

## 11. Within-domain control

`make_control_repeat.py` builds synthetic repeat frames from the same orthophoto squares
the teach library came from (rotated to the route bearing and resampled to the 906 px
capture geometry). Evaluated with the same `evaluate_ridf.py`, they give the
no-domain-gap baseline and test the evaluator: every frame must match its own waypoint
at 0°.

```powershell
python scripts\make_control_repeat.py --teach-root data\teach_innenstadt --alt 100 `
    --cache-dir data\teach_innenstadt\_cache_dop --out data\control_innenstadt\alt_0100m
python scripts\evaluate_ridf.py --teach-root data\teach_innenstadt --alt 100 `
    --repeat-manifest data\control_innenstadt\alt_0100m\manifest.csv `
    --workers 8 --out results\control_innenstadt\alt_0100m
```

Control altitudes in the thesis (`results_summary/control/`): Innenstadt 30, 40, 50, 60,
80, 100, 140, 200, 300 m; Sudbrack 30, 45, 100, 300 m; forest 45, 100, 300 m; agriculture
30, 45, 100, 300 m.
`--yaw-offset 30` is a sign check: the RIDF minimum must then lie at −30°.

## 14. Closed-loop route recapitulation

`recapitulate_route.py` implements the arc-scan agent of Gaffin et al. (Fig. 3):

1. initial heading from the RIDF of one capture at the start;
2. per step, 7 candidates on an arc of radius `--step-m 10` m at 0, ±15, ±30, ±45°;
3. each candidate is captured and matched against all teach scenes;
4. move to the most familiar candidate (`gaffin_ratio = d_best / mean(D)`); the arc is
   always scanned completely, because across the domain gap the ratio of a correct
   match is about 0.6 and Gaffin's early stop at 0.20 never triggers;
5. next scan direction: `--heading-mode compass` (visual compass estimate, used for all
   systematic runs) or `extend` (Gaffin; the default);
6. stop at `goal` (≤ 15 m from the route end), `lost` (> 60 m from the route) or
   `max_steps` (2 × route length / step = 126).

The agent never sees the route; cross-track distance and localization error are only
logged for the evaluation.

```powershell
# one simulator run
python scripts\recapitulate_route.py --world sim --route routes\route_s.csv --alt 100 `
    --teach-root data\teach_innenstadt --heading-mode compass `
    --origin-lat 52.040111 --origin-lon 8.495097 --origin-h 800 `
    --ground-z0 640 --sim-config sim_config --workers 12 `
    --out data\recap\innenstadt_alt0100m_compass

# the systematic 3 x 3 grid of the thesis (about one hour of simulator time per run)
.\scripts\run_recap_grid.ps1

# same agent without simulator: fresh orthophoto crop per candidate
python scripts\recapitulate_route.py --world wms --route routes\route_s.csv --alt 50 `
    --teach-root data\teach_innenstadt --heading-mode compass `
    --cache-dir data\recap_ctrl\_cache_dop --workers 12 `
    --out data\recap_ctrl\innenstadt_alt0050m_compass

# table and trajectory figures (rows = routes, columns = altitudes)
python scripts\aggregate_recap.py --runs <run folders> --out data\figs_recap_grid --cols 3
```

Each run folder holds `params.json` (complete configuration), `candidates.csv` (one row
per capture), `steps.csv` (one row per step) and, after termination, `summary.json`.
The logs of the reported runs are in `results_summary/closed_loop/runs/`; their paths in
`params.json` (e.g. `route_s.csv`, `data\teach_rgb`) are relative to the folder the runs
were started from. The preliminary Innenstadt run at 45 m with `compass` ended after 35 steps
before any termination criterion fired (all steps `running`) and therefore has no
`summary.json`.

## 16. Reproducibility notes

- **One preprocessing implementation.** Teach and repeat both import
  `snapshot_lib.py`; do not reimplement any step of the chain.
- **Axes.** With an unrotated CesiumGeoreference, Unreal's +X points east, so AirSim's
  NED x axis has the compass bearing 90° (`--ned-x-bearing 90`). A systematic RIDF
  heading offset of ±90° or 180° means this value or the georeference rotation is wrong.
- **Altitude** is above ground level. The ground is measured at every waypoint from the
  planar depth image (95th percentile = street level), not taken from a global terrain
  height.
- **Settling.** Cesium streams tiles asynchronously, so frames are accepted only when two
  consecutive captures differ by less than `--settle-thresh` (mean absolute gray
  difference) and at least 99.5 % of the depth pixels are valid. A visually static view
  still differs by 0.49–0.51 gray levels between frames (renderer noise, consistent with
  temporal anti-aliasing), so the default of 0.5 only times out; the thesis used 0.6
  (Innenstadt) and 1.0 (Sudbrack, Nordpark, all closed-loop runs).
- **Live tiles.** The 3D tiles are streamed from Google via Cesium ion and can be
  updated by Google; frames captured later may therefore differ from the thesis frames.
- **`--resume`** skips waypoints already in a manifest. Use a new output folder whenever
  the acquisition conditions change. `evaluate_ridf.py` overwrites its output folder.
- **Changes after the reported experiments.** The scripts are the ones that produced
  the thesis results, with these later changes:
  - `capture_repeat.py`: two robustness fixes from 14 Sep 2026 for the case that the
    depth camera hits nothing (float16 saturation at 65 504 m): such values are no
    longer used as ground, and the waypoint is retried from a safe height. Before the
    fix this failure was self-indicating (black frames, `agl_measured_m` = 65 504); valid
    frames are not affected.
  - `extract_route_snapshots.py`: new option `--layer` (default unchanged, `nw_dop_rgb`).
  - `probe_sim.py`, `selftest_recap.py`, `fig_arc_scan.py`: paths made to work from the
    repository root; plot labels and comments translated to English; docstrings updated.
  - `aggregate_recap.py` is the version used for the thesis tables and figures
    (`--cols`, explicit handling of incomplete runs).
  - `recapitulate_route.py` is unchanged; it produced all closed-loop runs.

## 17. Troubleshooting

| Symptom | Cause / fix |
|---|---|
| `import projectairsim` fails | client not installed in the active environment (Section 4) |
| `probe_sim.py --stage 1` cannot connect | Unreal not in Play mode; the level must run Project AirSim like the Blocks map (World Settings → GameMode) |
| `--sim-config` error / `TypeError` in `os.path.join` | `--sim-config` has no default; pass `sim_config` |
| `set_pose` returns `False` | robot is not non-physics; check `robot_quadrotor_nadir_nonphysics.jsonc` |
| black or patchy frames in stage 4/5 | tiles still streaming (wait / raise settle time); check the ion token; `Chase` camera must point nadir |
| black frames and `agl_measured_m` = 65504 | no 3D mesh under the camera (e.g. flat forest areas outside photogrammetric coverage) |
| sun almost on the horizon, very long shadows | CesiumSunSky time zone still −5.0; set +2.0 |
| Unreal crashes when lighting is queried | `get_time_of_day()` / `get_sunlight_intensity()` crash with CesiumSunSky; leave `--query-lighting` off |
| every frame hits the settle timeout | threshold at the renderer noise floor; use 0.6–1.0 |
| RIDF heading consistently ±90° or 180° off | `--ned-x-bearing` / georeference rotation |
| localization errors of hundreds of metres with vegetation-heavy scenes | teach library from the wrong WMS layer (must be `nw_dop_rgb`) |
| truncated WMS images | `verify_cache.py --delete`, then rerun the extraction |
